# pvault 手动验证清单

这份清单是留给人（在真实浏览器里）逐条勾选验证的。

为什么需要它：**IndexedDB 是浏览器 API，Node 里不存在**，所以 `app/db.js` 这一层的读写行为
无法用 `node --test` 自动覆盖（本项目的零依赖约束也排除了引入 fake-indexeddb 之类的 polyfill）。
可以自动测的部分已经放在 `tests/schema.test.js`：`app/schema.js` 的种子数据与仓库定义是纯函数，
没有任何浏览器全局引用，因此能在 Node 里直接 import 并断言。

验证环境：`npm run dev` → 浏览器打开 `http://localhost:8080` → 开发者工具。
每一步的勾选框都应当在**真机浏览器**里实际观察过后再打勾。

## 数据层

- [ ] 首次打开：IndexedDB 中出现 pvault 库，含 5 个对象仓库（txns / accounts / categories / receivables / settings）
  - 位置：开发者工具 → Application → Storage → IndexedDB → pvault
- [ ] 首次打开：分类 12 条、账户 5 条被自动写入
  - 控制台：`const db = await import('./app/db.js'); (await db.getAll('categories')).length` → 期望 `12`
  - 控制台：`(await db.getAll('accounts')).length` → 期望 `5`
- [ ] 刷新页面后不会重复写入种子数据（settings 仍只有 5 条）
  - 控制台：`(await db.getAll('settings')).length` → 刷新前后都是 `5`
- [ ] 删除浏览器站点数据后重新打开，种子数据重新生成且旧交易消失（这是预期行为）
  - 位置：Application → Storage → Clear site data，然后刷新
- [ ] `txns` 上存在 `by_occurredAt` 与 `by_kind` 索引，`categories` 上有 `by_kind`，`receivables` 上有 `by_settledAt`
  - 位置：Application → IndexedDB → pvault → 展开仓库 → Indexes

### 查询边界（`getByRange` 的上界开区间）

- [ ] 区间查询不包含上界那一瞬间：`getByRange('txns', 'by_occurredAt', 本月1日0点, 下月1日0点)`
      不返回 `occurredAt === 下月1日0点` 的交易
- [ ] 空区间（lower === upper）不抛错：`await db.getByRange('txns', 'by_occurredAt', t, t)` 返回 `[]`
      - 备注：现行 W3C IndexedDB 3.0 规范里 `IDBKeyRange.bound()` 只在 `lowerKey > upperKey` 时抛
        `DataError`，两边相等且上界开放时是空区间；但 MDN 的异常表仍写着「lower 与 upper 相同且任一
        边界开放 → DataError」，属于旧版描述。若这条在真机上抛错，说明需要给空区间加特判。

## 仓库层
- [ ] 新增一笔支出后，当月查询能查到，删除后查不到
- [ ] 带分摊的交易会同时生成一条「应收」，金额与分摊一致
- [ ] 删除（撤销）一笔带分摊的交易后，它派生的未结清应收一并消失，且首页应收金额同步减少
- [ ] 转账不计入月度支出统计（在控制台用 `summary.monthlyTotals` 验证）
- [ ] 设置项读写正常（`budgetTotalCents` 改完刷新仍在）
- [ ] `settleReceivable` 后该条 `settledAt` 有值，且 `receivableSummary` 不再计入它
- [ ] 归档的账户与分类不出现在 `listAccounts` / `listCategories` 结果里
- [ ] 人为让数据层出错（控制台执行 `const db = await import('./app/db.js'); await db.put('settings', {})`，缺 keyPath 会失败），界面应显示「页面加载失败：…」而不是白屏，且 Tab 栏仍可见可点
- [ ] 数据层首次失败后能自愈：清空磁盘配额或恢复后，不需要刷新页面，再次操作即可成功

## 应用外壳

- [ ] 底部出现三个 Tab：记账 / 统计 / 密码箱，点击能在三个视图间切换
- [ ] 切换后 URL hash 变化（`#/ledger` `#/stats` `#/vault`），刷新后停在同一 Tab
- [ ] 直接访问非法 hash（如 `#/nope`）会退回记账页
- [ ] 带 query 的 hash（如 `#/ledger?new=1`）也停在记账页，而不是被当成非法路由退回
- [ ] 密码箱 Tab 显示「密码箱将在下一步实现」占位文字
- [ ] 手机上加到主屏后，Tab 栏不被底部手势条遮挡（安全区适配生效）
- [ ] 页面加载出错时显示错误文字且 Tab 栏仍可见（而不是整页白屏）

    期望看到「页面加载失败：boom」且底部 Tab 仍可点击切换

## 记账首页

- [ ] 月份标签与今天日期正确（今天/昨天/9月20日 三种形态）
- [ ] 隐藏金额开关生效（大数字、今日流水的金额都变模糊），刷新后状态保持
- [ ] 未设预算时不显示预算卡；设了之后显示进度条、已用百分比、还剩、日均可用
- [ ] 预算进度条颜色：<80% 绿、80~100% 黄、>100% 红
- [ ] 有应收时显示「应收 ¥xx」，没有时不显示
- [ ] 今天没有交易时显示「今天还没有记账」
- [ ] 今日流水按时间倒序，每条带分类 emoji、分类名、账户名
- [ ] **当天流水的金额是交易原始金额**（不含分摊扣减），只有月度汇总扣减他人分摊——确认这个语义符合预期
- [ ] 数据层出错时不白屏（由 main.js 的 try/catch 兜底显示错误文字）

- [ ] 点右下角 + 后，录入面板从底部滑出，上半屏仍能看到首页内容

- [ ] 面板打开时背景不跟随滚动；关闭后恢复滚动
- [ ] 数字键盘显示区初始为 `0`；依次点 1、2、.、5 显示 `12.5`
- [ ] 连点两个小数点只生效一个；小数位最多两位；整数位最多九位；前导零被替换

- [ ] 面板在小屏手机上不超过 78vh，且底部不被手势条遮挡（安全区适配）

## 录入面板

- [ ] 点右下角 + 后，面板从底部滑出，数字键盘已就位（无需额外点击）
- [ ] 中午打开时分类默认高亮「餐饮」；傍晚默认「交通」（需先积累几笔历史）
- [ ] 输入金额 → 点完成 → 面板收起、首页立即出现这一笔、且能核对到账户名
- [ ] 记完 3 秒内出现「已记一笔 / 撤销」浮层；点撤销后该笔消失、首页应收金额同步减少
- [ ] 浮层 3 秒后自动消失；消失后再点不到撤销
- [ ] 切换到「转账」→ 分类九宫格消失、出现两个账户选择；目标账户与来源相同时完成按钮禁用
- [ ] 切换到「收入」→ 分类换成收入类，已输入金额保留
- [ ] 勾「有人分摊」→ 填金额超过总额时完成按钮禁用并显示红色提示
- [ ] 账户默认是上次用的那个（用信用卡记一笔后再打开，默认仍是信用卡）
- [ ] 时间默认现在，改成别的时间后记录显示在对应日期
- [ ] 提交失败时（可人为制造：控制台临时改 store.addTransaction 抛错）面板不关闭、显示错误文字、可重试

### 录入面板的边界情况（静态推演时补的，值得真机确认）

- [ ] 金额为 0（点键盘 0 后直接完成）时按钮**可点**，能记下一笔 0 元交易——
      `cents === null` 才是「没输入」，0 是合法金额
- [ ] 金额输错后整体重来：⌫ 删到空显示 `0`，此时按钮重新变灰
- [ ] 分摊行填了金额但没填姓名 → 该行不进分摊；填了姓名没填金额 → 同样不进
- [ ] 勾了分摊并填好金额后取消勾选 → 提示行消失、完成按钮恢复可点，且提交后**不带分摊**
- [ ] 分摊行按 ✕ 删除后，剩余行的姓名与金额不串位、合计跟着变
- [ ] 备注输入到一半时点分类格子 → 焦点会离开输入框，但已输入的备注文字仍在（状态回填）
- [ ] 快速双击「完成」只记一笔（面板收起有 180ms 动画，期间按钮已锁）
- [ ] 撤销浮层里快速双击「撤销」只删一次，不会报错也不会重渲染两次
- [ ] 连续记两笔：第一笔的浮层被第二笔顶掉（浮层只保留最新一个）
- [ ] 在日期控件里把时间清空 → 不写入非法时间（仍用上一次的有效时间提交）
