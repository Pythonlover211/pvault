# pvault 手动验证清单

这份清单是留给人（在真实浏览器里）逐条勾选验证的。

为什么需要它：**IndexedDB 是浏览器 API，Node 里不存在**，所以 `app/db.js` 这一层的读写行为
无法用 `node --test` 自动覆盖（本项目的零依赖约束也排除了引入 fake-indexeddb 之类的 polyfill）。
可以自动测的部分已经放在 `tests/schema.test.js`：`app/schema.js` 的种子数据与仓库定义是纯函数，
没有任何浏览器全局引用，因此能在 Node 里直接 import 并断言。

验证环境：`npm run dev` → 浏览器打开 `http://localhost:8080` → 开发者工具。
每一步的勾选框都应当在**真机浏览器**里实际观察过后再打勾。

### 完全没有被自动测试覆盖的（必须由人工在真机上过一遍）

- **所有 IndexedDB 真实读写**：`db.js` / `store.js` / `vault-store.js` / `backup-store.js` 的落库、
  事务原子性、索引区间查询边界。本项目零依赖，不引 fake-indexeddb，Node 里也根本没有 IndexedDB。
- **加密保险库的端到端**：初始化 → 写条目 → 刷新 → 重新解锁 → 改主密码 → 用恢复码解锁这一整条链，
  以及空闲 5 分钟自动上锁。密钥链路的每一段在 Node 里单独测过，但「浏览器真的这么跑」没测过。
- **所有界面**：三个 Tab、各面板、密码箱三态、条目编辑、备份面板的真实渲染、排版、焦点、
  输入法与滚动锁。开发环境里没有浏览器，这些界面**从未被真正渲染过**。
- **剪贴板**：复制成功，以及 30 秒后自动清空（`navigator.clipboard` 需要权限与安全上下文）。
- **文件下载与文件选择**：导出 `.pvault` 真的下载下来、`<input type="file">` 真的唤起系统选择器。
- **Service Worker**：install / activate / fetch 三段、离线可用性、版本更新与自动刷新。
  目前只做过静态核对：`node --check sw.js`、ASSETS 逐条请求 200、ASSETS 与磁盘文件双向对齐。
- **PWA 安装**：添加到主屏幕、独立窗口、桌面图标角标、长按快捷方式。

因此下面每一条都必须在真机上人工勾选，尤其是「密码箱（数据层）」「备份与恢复」「密码箱（界面）」
「密码箱条目编辑」「备份与恢复（界面）」「PWA 与离线」几节 —— 计划 2 的全部交付都落在那里。

### 查询边界（`getByRange` 的上界开区间）

- [ ] 区间查询不包含上界那一瞬间：`getByRange('txns', 'by_occurredAt', 本月1日0点, 下月1日0点)`
      不返回 `occurredAt === 下月1日0点` 的交易
- [ ] 空区间（lower === upper）不抛错：`await db.getByRange('txns', 'by_occurredAt', t, t)` 返回 `[]`
      - 备注：现行 W3C IndexedDB 3.0 规范里 `IDBKeyRange.bound()` 只在 `lowerKey > upperKey` 时抛
        `DataError`，两边相等且上界开放时是空区间；但 MDN 的异常表仍写着「lower 与 upper 相同且任一
        边界开放 → DataError」，属于旧版描述。若这条在真机上抛错，说明需要给空区间加特判。
