# pvault 安卓打包说明

把 pvault 打成能装到手机上的 APK。**静态资源全部内置在包里**，装上就永久离线可用，
不依赖 GitHub Pages、不依赖任何服务器，数据只存在设备本地。

---

## 为什么是「本地打包」而不是「网页壳」

两种做法都能出 APK，选前者是因为：

| | 本地打包（现在这个） | 网页壳 |
|---|---|---|
| 离线可用 | 装上就永久可用 | 首次要联网，之后靠 Service Worker |
| 依赖外部 | 无 | 依赖 GitHub Pages 可用性 |
| 改功能后 | 要重新出 APK 覆盖安装 | 推代码后手机自动是新版 |
| 华为/鸿蒙设备 | 正常（用系统 WebView） | 有风险（网页壳依赖 Chrome 的 Custom Tabs，这类设备常常没有 Chrome） |

## 环境（已经装好，全部在 D 盘）

`D:\temp\android\` 下：

| 目录 | 内容 | 体积 |
|---|---|---|
| `sdk\` | Android SDK（commandline-tools + platform-tools + android-34 + build-tools 34.0.0） | 4.7 GB |
| `avd\` | 模拟器镜像与 AVD | 8.3 GB |
| `gradle-home\` | Gradle 依赖缓存 | 0.4 GB |
| `jdk\` | 独立 JDK 21（刻意不用系统里那个 `D:\abaqus` 的，避免以后 ABAQUS 一动构建链就断） | 0.3 GB |
| `gradle-8.9\` | Gradle 发行版 | 0.1 GB |
| `keystore\` | 签名密钥与口令（**仓库外**，仓库是公开的，绝不能提交） | — |

已设的用户级环境变量（所以任何安卓构建都不会再往 C 盘写东西）：
`ANDROID_SDK_ROOT` / `ANDROID_HOME` / `ANDROID_USER_HOME` / `ANDROID_AVD_HOME` /
`GRADLE_USER_HOME` / `JAVA_HOME`。

> **为什么放在 `D:\temp` 而不是 `D:\Android`**：D 盘根目录的 ACL 不允许普通用户
> （当前账户 `lenovo` 非管理员）新建文件夹。想换成 `D:\Android` 的话，先用管理员权限
> 建好目录并授权，再改 `scripts/setup-android.ps1` 与 `scripts/build-apk.ps1` 里的默认路径。

## 首次安装环境

```powershell
# 1. 下载 commandline-tools（约 146 MB）
curl.exe -L -C - --retry 6 --retry-all-errors `
  -o "D:\temp\android\commandlinetools.zip" `
  "https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip"

# 2. 解压 + 接受许可 + 装组件（约 394 MB）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/setup-android.ps1

# 3. Gradle（约 130 MB）
curl.exe -L -C - --retry 6 --retry-all-errors `
  -o "D:\temp\android\gradle-8.9-bin.zip" `
  "https://services.gradle.org/distributions/gradle-8.9-bin.zip"

# 4. 独立 JDK（约 196 MB）
curl.exe -L -C - --retry 6 --retry-all-errors `
  -o "D:\temp\android\jdk21.zip" `
  "https://api.adoptium.net/v3/binary/latest/21/ga/windows/x64/jdk/hotspot/normal/eclipse"
```

> 用 `curl.exe` 而不是 `Invoke-WebRequest`：后者下大文件经常 `unexpected EOF` 中断。
> `-C -` 支持断点续传。脚本文件必须存成 **UTF-8 with BOM**，否则 PowerShell 5.1
> 会把中文注释读成乱码并破坏语法。

## 构建

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-apk.ps1
# 产物：dist\app-release.apk
```

脚本做三件事：把仓库根目录的静态站点复制进 `android/app/src/main/assets/www/`
（这个目录是**构建产物**，不进版本管理，免得同一份代码有两份副本）→ 调 Gradle
`assembleRelease` → 把 APK 收到 `dist/`。

改动前端代码后重新打包时，**记得同时把 `sw.js` 的 CACHE 版本号 +1**（PWA 那边要靠它
刷掉旧缓存；APK 内不走 SW，但不加会让人误以为没更新）。

## 签名

密钥在 `D:\temp\android\keystore\pvault-release.jks`，口令在同目录的
`keystore.properties`（`android/app/build.gradle` 会去读它）。

**这两样东西丢了就没法再发布能覆盖安装的升级包**——只能卸载重装，数据会一起没。

## 发布

推 main 后手动建 Release 并传 APK：

```powershell
# 凭据从 git 的凭据管理器取（token 不回显）
$token = ((("protocol=https`nhost=github.com`n" | git credential fill) 2>$null) |
  Where-Object { $_ -match '^password=' }) -replace '^password=',''
```

注意两点：GitHub 在国内**直连不稳**，API 与 push 都要走 `-Proxy http://127.0.0.1:7897`
（Clash）；传含中文的 JSON 时 **必须显式转成 UTF-8 字节数组**，否则 PowerShell 5.1 会用
Latin-1 编码，GitHub 直接返回 400。

## 真机 / 模拟器调试

壳里开了 WebView 远程调试，可以用 CDP 直接驱动页面（读 DOM、模拟点击、看控制台、截图）：

```powershell
$adb = "D:\temp\android\sdk\platform-tools\adb.exe"
$appPid = ((& $adb shell pidof dev.pvault.app) -join '').Trim()
& $adb forward tcp:9333 "localabstract:webview_devtools_remote_$appPid"
# 然后 GET http://127.0.0.1:9333/json/list 拿 webSocketDebuggerUrl，用 Node 连它
```

**这个能力很值钱**：`structuredClone` 缺失导致备份导出不可用那个 bug，就是靠它抓到的——
光看代码看不出来（Node 和桌面浏览器里这个 API 都存在），只有在一个 WebView 版本足够旧的
真实安卓环境里点一下「导出」才会暴露。而当时靠截图估算坐标去点按钮误差太大，
点「备份与恢复」反而把面板关掉了。

> 模拟器启动：`emulator -avd pvault-test -no-window -gpu swiftshader_indirect`
> （需要 WHPX 硬件加速；`emulator -accel-check` 可查）

## 已知限制

- **最低安卓 8.0（API 26）**，因为用自适应图标。你的手机远高于这个。
- **卸载 App 会连同数据一起删掉**。重要数据先用「备份与恢复」导出。
- 导入账单时选文件走系统文件选择器；如果某台设备的文件管理器对 `content://` 支持不好，
  可能选不到文件（未在真机上验证）。
- 后端串列的数据（如 `.xlsx`）不支持，只吃 CSV。
